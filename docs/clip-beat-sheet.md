# 대표 클립 비트 시트 (one-take share)

> - **상태**: 완료 기록 (촬영 가이드)
> - **목적**: three.js 커뮤니티에 올릴 **한 테이크** 공유 클립의 안무·타이밍·기본값을 사람이 따라 찍을 수 있게 정리한다.
> - **범위**: 제품 기능이 아니다. 인앱 녹화 버튼을 만들지 않는다 — **OS 화면 녹화**만 쓴다.
> - **관련**: [`look-grammar.md`](look-grammar.md) (장르·리트윗 테스트), [`oriental-painting-research.md`](oriental-painting-research.md) §2 (삼원법), [`demo-analysis.md`](demo-analysis.md) (바이럴 공식), [`project-status.md`](project-status.md) (목표·녹화 보류), `CLAUDE.md` 프로젝트 목표 ②.

## 1. 한 줄 목표

**석양 역광 속에서 집이 부재 단위로 서고(약 10초 조립), 처마가 주선으로 읽힌 뒤 마을이 산수처럼 열린다.**  
생성 *과정*이 미디어다 — 완성 스톡 샷만 돌리는 클립이 아니다.

프로젝트 목표 ②의 기준 산출물: 공식 three.js 채널·커뮤니티에 올려도 "어떻게 만들었지?"가 나오는 **단일 샷**.

## 2. 삼원법 시간축

산수 삼원(고원 → 심원 → 평원)을 **한 테이크의 시간 순서**로 쓴다. 카메라 프리셋을 새로 짜는 작업이 아니라, 이미 있는 진입·focus·부감 경로를 이 순서로 밟는 촬영 규약이다.

| 원 | 화면에서 읽히는 것 | 제품 경로 |
| --- | --- | --- |
| **고원** | 집·처마가 크게, 실루엣이 주선. 조립이 여기서 일어난다. | 히어로 랜딩 / 종가 focus — 망원·문 높이 착지, 처마곡이 프레임을 가로지름 |
| **심원** | 배산임수 부감, 능선·숲이 겹쳐 넘겨다보임 | 브레드크럼·ESC로 둘러보기(마을 배율) |
| **평원** | 가까운 능선에서 먼 산·하늘 밴드로 수평 시선 | 부감 후 약한 오빗/팬, 또는 규모·계절 크로스페이드 |

핵심 비트는 **고원의 조립(~10s)** 이다. 심원·평원은 여운이며 잘라도 클립이 성립한다.

## 3. 샷 시퀀스 (대략 타이밍)

시계는 **Enter 클릭(또는 동등 진입 제스처) = t = 0**.  
사전 로드·타이틀 대기는 녹화 전 또는 클립 앞 0.5–1.5초만 남긴다.

| 구간 | t (초) | 내용 | 촬영 메모 |
| --- | ---: | --- | --- |
| 0. 타이틀·로드 | 녹화 전 | 무거운 생성은 타이틀/로딩 창에서 끝난다. 씬은 숨긴 채 준비. | 진입 직전 프레임 레이트·오디오 컨텍스트만 확인. 빈 터를 길게 보여 주지 말 것. |
| 1. 진입·베일 | 0.0 – ~1.1 | 먹안개 베일 아래 빈 터. 착공 지연 ≈ **1.1s** (`HERO_ASSEMBLE_DELAY_MS`). | **유휴 구간 — 늘리지 않는다.** 타이틀 페이드와 착공이 맞물린 길이. |
| 2. 건축 리빌 + **조립(본편)** | ~1.1 – ~11.1 | `playAssembly` **duration 10.0s**. 기단→기둥→벽·창호→(공포)→지붕 리플. 카메라는 조립 완주보다 약 **1.3s 먼저** 고정 프레임에 도착해 마지막 부재 착지를 흘리지 않는다. | 한 테이크의 **주 비트**. 두부(tofu) 탄성·모멘텀 정착이 지붕의 무게로 읽혀야 한다. 크로마는 3s idle 후 페이드 — 보통 손 떼면 씬만 남는다. |
| 3. 정착 홀드 | ~11 – ~14 | 고정 근접 프레임. 모트·연기·등롱 등 근접 링이 피어남. 림·블룸 헤이즈. | 고원 여운 2–3초. 손떨림·휠 줌 금지. |
| 4. *(선택)* 심원 개방 | +3 – 6 | 마을 브레드크럼 / ESC → 부감. 배산·숲·필지가 한 그릇으로. | 조립 직후 바로 끊지 말고 1박 둔 뒤. 마을이 화면 약 65–75%. |
| 5. *(선택)* 평원·규모·계절 | +3 – 8 | 약한 오빗, 규모 슬라이더, 또는 계절 크로스페이드(팝 없이). | 본편보다 짧을 것. 새 기능 시연이 아니라 **같은 세계의 숨**만. |

**권장 총 길이**

- **본편 only (고원)**: 약 **14–16초** — 트윗/루프에 가장 단단하다.
- **삼원 풀**: 약 **20–28초** — 심원·평원을 붙여 “마을 생성기” 서사를 덧붙일 때.

## 4. 카메라·시간·시드 기본값

플래그십 룩은 코드 기본과 같다. 샷 하네스(`?shot=1`)는 비교용 **day** 를 쓰므로 **공유 클립에는 쓰지 않는다.**

| 항목 | 권장 | 이유 |
| --- | --- | --- |
| 시간 | **sunset** (앱 기본, 히어로 조립 중 강제) | 골든아워 역광 림 + bloom 헤이즈 — [`look-grammar.md`](look-grammar.md) 통합자 |
| 노을 스타일 | gold (기본) 또는 취향에 따라 crimson/violet | 한 테이크 안에서는 바꾸지 말 것 |
| 계절 | summer 또는 autumn | 채도 규율 안에서 림·수목이 분리되어 읽힘 |
| 날씨 | clear | 비·눈은 본편 조립을 가리기 쉽다. 별 클립으로. |
| 규모 | **village** (또는 hamlet) | 조립 가독 + 직후 부감이 과밀하지 않음. 규모 비트만 capital/hanyang. |
| 시드 | **7** (게이트·측정 상시 사용) 또는 미리 고른 고정 시드 | 재촬영 재현. URL/UI에 시드를 박고 들어간다. |
| 수묵 | 기본 PBR 석양 | 수묵은 별 클립. 한 테이크에 景→墨 토글을 넣지 말 것. |
| 오디오 | 켜 둠 (genesis → 석양 트랙 핸드오버) | 화면 녹화에 시스템 오디오 포함 시. 무음 업로드면 무시. |
| 해상도 | 1080p 이상, 창 크롬 최소 | 브라우저 전체 화면 또는 캔버스 영역만. |

**URL 스케치** (배포 도메인 기준; 로컬이면 origin만 바꿈):

```text
https://cheoma.midagedev.com/?seed=7&time=sunset
```

규모·시즌 쿼리가 UI와 다를 수 있으므로, 불확실하면 UI에서 seed 7 · 석양 · village 를 맞춘 뒤 새로고침 → 로드 완료 → 녹화 시작 → Enter.

## 5. 녹화 방법 (사람 손)

1. macOS: Screenshot toolbar **⌘⇧5** → Record Selected Portion / QuickTime Player → New Screen Recording. Windows: Xbox Game Bar / PowerToys 등.
2. **인앱 Record 버튼은 없다** — 감사에서 “녹화 없음”을 지적해도 만들지 않는다 (`project-status.md`, `CLAUDE.md`).
3. 진입 제스처 직전 0.5초부터 녹화 → 정착 홀드까지 한 호흡 → (선택) 부감·여운 → 정지.
4. 크로마가 거슬리면 마우스를 쉬게 두어 페이드아웃. 강제 CSS는 개발자 검증용이지 공개 클립 전제가 아니다.
5. 트림: 앞쪽 로딩 스피너는 자르고, **착공 직전 빈 터는 1초 전후만** 남긴다.

## 6. 하지 말 것

| 금지 | 이유 |
| --- | --- |
| **빈 터(empty-site) 유휴를 늘리기** | 조립을 길게 하는 것과 반대. `HERO_ASSEMBLE_DELAY`·타이틀 뒤 공백을 키우면 클립이 죽는다. 늘어난 시간은 **화면 위 시공**에만 쓴다. |
| **인앱 클립 녹화 UI** | 제품 범위 밖. OS 녹화로 충분. |
| 조립 중 휠·드래그로 카메라 뺏기 | 리빌 중단은 가능하지만 대표 테이크는 자동 경로 완주. |
| 정오·flat day 조명으로 본편 촬영 | 림이 죽으면 장르가 게임 스크린샷으로 전락. |
| 숲을 비워 “깔끔한” 구도 만들기 | 한국 산 룩의 본체. 성능 타협으로 숲을 깎지 않는다. |
| 조립을 통짜 스케일-인으로 대체 | 부재 리플·시공 순서가 공유 미디어의 훅. |
| 한 테이크에 편집 패널·리롤·수묵·규모를 전부 넣기 | 메시지 분산. 본편은 조립 하나. |
| 절대 wall-clock 벤치를 클립 근거로 쓰기 | 헤드리스 수치는 증거 아님. 프레임이 그림인지만 본다. |

## 7. 성공 판정 (촬영 직후)

1. **리트윗 테스트** — 정지 프레임만 봐도 처마·림·대기가 한 그림인가 (`look-grammar.md` §4).
2. **생성 과정이 보이는가** — 기단이 먼저, 지붕이 마지막; 이웃 부재 리플이 “아주 약간의 시차”로 읽히는가.
3. **무게** — 지붕이 착지할 때 탄성이 접근 속도에서 오고, 착지 후 따로 노는 출렁임이 아닌가.
4. **삼원** — 본편만이면 고원 완결; 풀 테이크면 고원 조립 → 심원 부감 → 평원 여운이 한 호흡인가.
5. **무음으로도 성립** — BGM 없이도 진행 리듬이 보이는가 (자막·나레이션 불필요).

## 8. 코드 상수 참고 (재촬영 시)

촬영 가이드가 제품 계약은 아니지만, 타이밍을 의심할 때 볼 곳:

| 상수 | 값 | 위치 |
| --- | --- | --- |
| `HERO_ASSEMBLE_DELAY_MS` | 1100 | `app/src/engine/engine.js` |
| `HERO_ASSEMBLE_DUR` | 10.0 | 동상 — 2026-07-26 클립 비트로 상향 |
| `HERO_REVEAL_TAIL` | 1.3 | 카메라가 조립 완주보다 먼저 고정 |
| tofu / ripple | `src/anim/assembly.js` | 단일 이징·기하 유도 리플; `npm run check:assembly` |

조립을 더 길게 쓰고 싶으면 **duration만** 늘리고 착공 지연은 고정한다. 게이트와 엔진 주석이 그 불변식을 전제로 한다.
