## 0. 요약

동양화의 나무는 **잎을 그리지 않는다. 붓점의 군집 리듬으로 잎덩이를 대신한다.** 그리고 그 덩이는
거리에 따라 형태를 버리고 농담(濃淡)만 남긴다. 현행 cheoma 나무는 이 두 축을 모두 놓치고 있는데,
원인은 "폴리곤이 적어서"가 아니라 **(a) 등축구·원뿔의 볼록하고 매끄러운 실루엣**, **(b) 면(facet) 노멀 때문에
수묵 모드가 캐노피 안쪽 폴리곤 경계를 전부 필선으로 그리는 것**, **(c) 계절색 휘도 폭이 너무 좁아
수묵 5단 양자화에서 한두 밴드로 뭉치는 것** 세 가지다. (b)와 (c)는 **드로우콜·삼각형 델타 0으로 고칠 수 있다.**

## 1. 동양화 나무 조형 문법

### 1.1 핵심 원리 7

**① 잎은 개체가 아니라 붓점의 군집이다 (점법 點法).**
동양화는 잎을 낱개로 묘사하지 않고 정형화된 붓점의 반복·중첩으로 잎덩이를 만든다. 점의 *형태*와
*군집 방식*이 수종을 결정한다. 밀양시립박물관 서화 용어에서 확인한 정의:

| 용어 | 정의(원문) | cheoma 번역 후보 |
| --- | --- | --- |
| 송엽점(松葉點) | "가늘고 끝이 뾰족하며 약 일곱 개씩 모여 반원형을 이룬 전법" | 소나무 근경 캐노피 카드 텍스처 = 7침 반원 로제트 |
| 협엽점(夾葉點) | "겹잎. 5∼6개의 잎 모양을 부채꼴을 이루도록 그린 것" | 활엽 근경 카드 = 5~6엽 부채꼴 |
| 백엽점(百葉點) | "측백나무나 **멀리 있는 큰나무**의 잎에 사용하는 점법" | 중경 활엽 잎덩이 |
| 세엽점(細葉點) | "위쪽으로 향해 자란 가늘고 긴 잎으로 어린 버들잎이나 대나무 잎에 사용" | 개울가 수종(선택) |
| 미점준(米點皴) | "중국 화가 미불이 창안한 것으로 산이나 땅에 윤곽이나 입체감을 부여하기 위해 사용한 점법" | 원경 수림대·능선 |
| 준(皴) | "바위나 산, 토파(土坡) 등의 표면을 처리하여 볼륨이나 질감을 나타내는 기본적인 필법" | 화강암 노두 대비축 |

핵심은 **점 하나가 아니라 "약 일곱 개씩 모여 반원형" 같은 군집 규칙**이 형태 언어라는 점이다.
현행 등축구/원뿔은 이 군집 리듬이 0이다.

**② 원경의 나무는 형태를 잃고 습윤한 점 덩어리가 된다 (미법산수 米法山水).**
미점법은 "산 표면과 나무 등을 **쌀처럼 생긴 짧은 횡점(橫點)을 포개듯** 찍어 묘사하는 기법"이고,
문헌이 명시한 적용 대상이 **"원경의 활엽수"**다. 화면 성격은 "구름이 자욱하고 수묵이 무성하며
강을 낀 깊은 산". 즉 원경 나무는 개별 실루엣을 포기하고 **겹친 점의 톤 덩어리**로 존재한다.
→ cheoma의 `forest-far` 블롭은 방향은 맞지만 표면이 매끄러운 이중 돔이라 "포갠 점"의 요철이 없다.

**③ 소나무는 굽은 줄기 + 층으로 벌어진 잎덩이(층운형)다.**
조선 산수의 주역인 소나무는 잎덩이를 수직으로 채우지 않고 **가지마다 옆으로 벌어진 층**으로 얹는다.
십장생도의 정형은 "화면 중앙으로 뻗어 올라간 소나무"이고, 잎 색이 변하지 않는 상록이라
"절개, 장수, 번성"의 상징을 진다. 같은 화면의 구름이 "상반부는 가로로 길게 퍼지는 모양,
하단은 뭉게구름처럼 동글동글하게 모여 있는 형상"으로 층화되는 것과 소나무 잎덩이의 층 구성은
같은 조형 감각이다. 겸재는 이 관습을 중국 화보 그대로 쓰지 않고 "중국식 틀을 벗어나
우리 산천에 맞게 변형한 소나무 표현"을 만들었다고 평가된다.
→ 현행 소나무 프로토는 **원뿔 2단 = 전나무/크리스마스트리 픽토그램**이다. 조형적으로 조선 적송이 아니다.

**④ 필선의 굵기·농도는 부위마다 다르다. 먹은 실루엣에 몰리고 내부에 적다.**
정선은 「금강전도」에서 "왼편 하단의 토산들은 피마준법과 미점법을 써서 표현하고, 그 외의 암산들은
수직준법(예리한 필선을 수직으로 그어 내리는 화법)으로 우뚝우뚝한 산세를 그렸다" — 즉 **대상 종류마다
다른 필법**을 배분한다. 실시간 수묵 선례도 같은 원칙을 지목한다: 수묵의 특징은 먹 농도의 변주이며
**"디테일보다 실루엣에 먹이 더 많이 실려 외곽 획이 내부 획보다 어둡게 보인다."**
→ 현행 수묵 모드는 모든 나무에 **같은 굵기·같은 농도**의 외곽선 + 내부 폴리곤선을 준다(§3.3 증거).

**⑤ 농담이 곧 깊이다. 균질한 회색은 실패다.**
「인왕제색도」는 "기존 산수화와 달리 멀리 보이는 인왕산을 앞의 경치보다 **오히려 짙게 덧칠**"해
화면을 강화했다. 즉 원근이 톤의 기계적 감쇠가 아니라 **의도된 값(value) 배분**이다.
`docs/ink-landscape.md`가 이미 이 원칙을 계약으로 갖고 있다("붓질 어휘를 명암에 번역").
→ 현행 나무 계절색의 휘도 폭이 너무 좁아 값 배분이 존재하지 않는다(§3.4).

**⑥ 여백은 정보의 부재가 아니라 대기 원근이다.**
인왕제색도의 산이 비와 안개로 비워진 공간 위에 떠오르듯, 밝은 종이색과 거리 감쇠는 깊이 표현이다.
수림대는 안개에 **잘려야** 한다 — 페이드로 옅어지는 것과 잘리는 것은 다르다.

**⑦ 구도는 부감 + 사선이고, 나무 군집은 능선을 따라 띠로 흐른다.**
정선은 "주로 높은 곳에서 비스듬히 아래를 내려보는 듯한 부감법의 시각으로 동적인 대각선이나 사선을
활용하여 화면을 구성"했다. 나무는 균등 산포가 아니라 **띠·군집**으로 방향을 만든다.
→ cheoma의 ecotone field·능선 편중은 이 축을 이미 부분적으로 갖고 있다(유지할 자산).

## 2. 실시간 3D 기술 선례

### 2.1 sumi-e 실시간 렌더 (Ōkami 계열)

Santiago Gallo Beruben, *Real Time Sumi-E Style Rendering Techniques*, MSc dissertation,
University of Dublin Trinity College, 2020 (지도 John Dingliana) — **PDF 본문 직접 판독.**
파이프라인: 엣지 검출 → 조명 여부별 외곽선 굵기 분리 → 스트로크 텍스처로 엣지 그리기 → wobble 왜곡 →
내부 셰이딩(톤 텍스처 또는 셀) → 종이 효과(알파) → 알파 임계 discard.

이 문서가 cheoma에 실제로 주는 것:

| 기법 | 내용 | cheoma 현황 |
| --- | --- | --- |
| **톤 텍스처** | 휘도로 1D LUT를 샘플(`u = clamp(0.3r+0.59g+0.11b), v = 0.5`). 셀 셰이더 대신 톤 텍스처를 쓰면 **"종이에 먹이 번지는 효과"**가 난다 | ink.js는 LUT 없이 5단 양자화 + fbm 디더로 같은 목적 달성 — **동등물 보유** |
| **lit/unlit 외곽선 굵기 분리** | `0 ≤ n·v ≤ mix(u, l, max(0, n·l))` — 빛을 받는 쪽과 안 받는 쪽 선 굵기를 다르게 | ink.js는 **깊이/노멀 불연속만** 씀. 조명 방향 종속 선 굵기 없음 — **미보유(원리 ④의 미구현분)** |
| **wobble UV 왜곡** | 스트로크 텍스처 UV에 오프셋을 줘 선을 흔든다. 과하면 내부 셰이딩과 어긋난다 | ink.js는 `brush`/`brushFine` fbm으로 두께·농도를 흔든다 — **동등물 보유** |
| **알파 = 1 − 평균색** | 어두운 색은 불투명(먹), 밝은 색은 투명(종이 배어남) + 알파 임계 이하 정점 discard = "종이 효과" | ink.js는 `grain`을 `tone`에 따라 섞어 같은 결과 — **동등물 보유** |

**가장 중요한 결론은 이 선례가 못 한 것이다.** 논문의 검증 대상은 Stanford Bunny와 구(球) 같은
**단일 매끄러운 오브젝트**이고, 나무·풀 같은 유기적 군집을 다루지 않는다. Ōkami 역시 배경 식생은
수작업 카드/텍스처다. → **스크린 스페이스 수묵 패스만으로는 나무가 회화적으로 되지 않는다.**
cheoma의 `ink.js`는 이미 이 문법의 대부분(농담 양자화·한지 결·붓 흔들림·여백 수렴)을 구현했으므로,
남은 결손은 패스가 아니라 **패스에 입력되는 기하 실루엣과 값 분포**에 있다. 이것이 이 리서치의 축이다.

- [Real Time Sumi-E Style Rendering Techniques (TCD, 2020) PDF](https://publications.scss.tcd.ie/theses/diss/2020/TCD-SCSS-DISSERTATION-2020-056.pdf) — 본문 직접 확인.
- Ōkami 아트 스타일 분석(2차 자료): 수묵의 특징을 "디테일보다 실루엣에 먹이 더 실린다"로 요약. 1차 기관 자료 아님 — credits 후보 아님.

### 2.2 회화적 폴리지 (지브리풍)

- **구체 노멀 전사(sphere normal transfer)** 가 이 룩의 핵심 기법이다. 가지에 구를 배치해 대략적 캐노피를
  조각하고, 그 위에 알파 카드를 흩뿌린 뒤, **나무 전체를 감싸는 구의 노멀을 카드에 전사**한다.
  카드가 자기 평면 노멀을 잃고 **하나의 둥근 덩이처럼 셰이딩**되어, 개별 카드가 분해되어 보이지 않는다.
  잎 색은 1~2색·낮은 러프니스로 유지해 후처리 없이 평면적·회화적 인상을 만든다.
  - [Kids With Sticks, Creating stylized art inspired by Ghibli using UE4 (2020-01)](https://kidswithsticks.com/creating-stylized-art-inspired-by-ghibli-using-unreal-engine-4/) — Blender DataTransfer 모디파이어로 노멀 전사, Auto Smooth 미활성 시 커스텀 노멀 무효, 양면 재질에서 커스텀 정점 노멀 사용 시 별도 처리 필요. **직접 확인.**
  - [BlenderNation, Creating Ghibli Trees in 3D](https://www.blendernation.com/2020/08/20/creating-ghibli-trees-in-3d/) — 노멀 편집 + 파티클 인스턴스 워크플로. 검색 요약 경유(**본문 미확인**).
- 이 기법이 cheoma에 특히 잘 맞는 이유: **구형 노멀은 런타임 비용이 0이다.** 프로토 지오메트리를 만들 때
  `normal = normalize(position − canopyCenter)`를 써 넣으면 끝이고, 드로우콜·프로그램·메모리 델타가 없다.
  그리고 **수묵 모드에도 즉시 듣는다** — `ink.js`의 내부 윤곽선은 노멀 불연속 Sobel이므로,
  노멀이 연속해지면 캐노피 안쪽 폴리곤선이 스스로 사라진다(§3.3).

### 2.3 WebGL/three 함정 (알파 카드를 쓸 경우)

- **alphaTest**는 순서 독립적이고 싸다. 커트아웃 실루엣에는 `transparent` 대신 이것을 쓴다.
  `transparent`는 카메라 거리 정렬에 의존하고 겹친 폴리지에서 근본적으로 실패한다.
- **alphaHash**는 정렬이 필요 없지만 노이즈를 남기고 TAA 같은 누적이 필요하다. cheoma에는 TAA가 없다.
  게다가 three r185는 **alphaHash를 공유 그림자 depth 재질에 복사하지 않아 알파 실루엣 그림자가 안 된다**
  (`src/render/shadow-depth-texture-lifecycle.js` 주석에 명기).
- **alphaToCoverage**는 MSAA 프레임버퍼가 필요하다. cheoma는 EffectComposer 체인이므로 부적합.
- 밀집 폴리지의 실제 비용은 삼각형이 아니라 **오버드로우·필레이트**다. 한양 40k 그루를 알파 카드로 바꾸면
  삼각형은 줄어도 프래그먼트가 폭발할 수 있다(§4-A 리스크).
- 근거: [three.js Material.alphaTest 문서](https://threejs.org/docs/#api/en/materials/Material.alphaTest),
  [three.js forum: Alpha test vs alpha hash](https://discourse.threejs.org/t/alpha-test-vs-alpha-hash/44493),
  [NVIDIA GDC 2017, Hashed Alpha Testing](https://developer.download.nvidia.com/assets/gameworks/downloads/regular/GDC17/RealTimeRenderingAdvances_HashedAlphaTesting_GDC2017_FINAL.pdf) — 목록은 검색으로 수집, **본문 정독은 three 문서/포럼 요약 수준(GDC PDF 미정독)**.

### 3.2 모드별 렌더 경로

**기본(회화) 모드**: `MeshStandardMaterial{flatShading:true}` → `injectCloudShadow`(산 숲만) →
`patchSnowMaterial` profile `foliage` → `createFresnelRim`. 최종 cacheKey는
산 숲 `cheoma-rim-physical-v1|cloudshadow-v1|snow-v2`, 외곽 산포 `cheoma-inst-fade-v2|cheoma-rim-physical-v1|snow-v2`.
- **림 그룹 배정 결함**: `rim.js`의 `ORGANIC_NAMES = {'trees','village-flora','focusGrass'}`는 이름 매칭이라
  `village-trees`(외곽 산포)·`village-forest`/`forest-trees`(산 숲)·`village-bloom`은 **매칭에 실패해 `misc`(×1.0)로
  림을 받는다.** 나무 재질에 `userData.role`도 없다. 즉 숲이 건물과 같은 계열의 강한 림을 받고 있고,
  의도된 organic ×0.7 감쇠는 단일건물 모드(`trees`)와 마당 flora(`village-flora`)에만 적용된다.
  HEAD와 작업 트리 양쪽에서 `ORGANIC_NAMES`와 실제 그룹명을 직접 대조해 확인했다.
  ⚠️ `src/env/rim.js`는 현재 림 담당 트랙이 작업 중(미커밋 변경 있음)이므로, 이 한 줄 수정은
  **나무 트랙이 직접 손대지 말고 림 트랙에 이관**한다.

**수묵 모드**: 나무는 별도 처리를 전혀 받지 않는다. `InkPass`가
(a) `scene.overrideMaterial = MeshNormalMaterial`로 노멀/깊이를 오프스크린 렌더하고,
(b) 그 버퍼의 깊이 Sobel = 실루엣 먹선, 노멀 Sobel = 내부 윤곽선,
(c) `RenderPass` 직후 캡처한 raw beauty의 휘도를 5단 양자화해 농담 워시를 만든다.
→ **나무의 수묵 표현은 전부 (기하 실루엣) × (instanceColor 휘도)의 함수다.** 둘 다 지금 잘못돼 있다.

### 3.3 결손 1 — 면 노멀이 캐노피 내부를 폴리곤선으로 그린다 (수묵 모드)

`shots/critters-ink.png`를 직접 열어 확인한 증상: 활엽 캐노피 안쪽에 **등축구 면 경계가 또렷한 필선으로
드러나고**, 소나무는 3단 원뿔이 각각 외곽선을 받아 **크리스마스트리 픽토그램**으로 읽힌다. 모든 나무가
같은 굵기·같은 농도의 선을 받아 원리 ④(실루엣에 먹이 몰린다)와 정반대다.

기계적 원인을 코드로 확정했다:
- three r185의 `PolyhedronGeometry`(= `IcosahedronGeometry`)는 **비인덱스**이며, `detail === 0`일 때
  three 자신이 `computeVertexNormals(); // flat normals`를 호출한다
  (`app/node_modules/three/build/three.core.js`).
- cheoma의 `makeBroadleafProto()`/`makeConiferProto()`는 병합 후 **다시** `computeVertexNormals()`를 호출한다
  (`src/village/forest.js:24,29`). 비인덱스 지오메트리에서 이것은 면 노멀을 고정한다.
- `InkPass`의 노멀 패스는 `MeshNormalMaterial`(기본 `flatShading:false`)로 **지오메트리의 노멀 속성을
  그대로 읽는다** — 즉 제품 재질의 `flatShading:true`와 무관하게 **면 노멀이 노멀 버퍼에 들어간다.**
- `ink.js`의 `crease`는 그 버퍼의 4방향 노멀 내적 Sobel이다. 면 경계마다 내적이 급락 → 필선.
  `normalEdge`가 0.24로 낮고 `detailFar`(70~230m)로 원경은 억제하지만, **근경·중경 나무는 그대로 통과한다.**

**따라서 캐노피 노멀을 구형화하면(§2.2) 이 필선은 셰이더 수정 없이 사라진다.** 단
제품 재질의 `flatShading: true`는 프래그먼트 도함수로 노멀을 재계산하므로 **커스텀 정점 노멀을 무효화한다** —
기본 모드에서도 효과를 보려면 나무 재질의 `flatShading`을 끄는 것이 전제다.

> 참고로 `gardens.js`의 보호수 캐노피는 `Icosahedron(r, 1)`(detail 1)이라 이미 정규화된 반경 노멀을 갖는다.
> 즉 저장소 안에 "부드러운 캐노피 노멀"의 선례가 이미 있다.

### 3.4 결손 2 — 계절색 휘도 폭이 좁아 농담이 층화되지 않는다 (R7의 나무측 실체)

`forest-crunch.js:142-153`의 여름 팔레트는 소나무 `0x2f4726`~`0x38562e`, 활엽 `0x445f2c`~`0x5e7d3d`~`0x445f2c`.
sRGB 휘도로 환산하면 대략 0.16~0.28 구간에 전부 몰려 있다. `ink.js`는 raw beauty를
`pow(srgb, 1/2.2)` 후 `levels = 5.0`으로 양자화하는데, 이 좁은 폭은 조명 편차를 얹어도 **1~2개 밴드**로
수렴한다. 결과가 "균질한 회색 수림" — `look-grammar.md` §3이 수묵 모드 실패 조건으로 명시한 바로 그 상태이고,
감사 R7("먹 농도·대비 저하")의 나무측 원인이다.

원리 ⑤(농담이 깊이다, 인왕제색도는 원산을 오히려 짙게)를 적용하려면 **거리·고도·수종에 따라
휘도 폭을 의도적으로 벌려야** 한다. 그리고 이것은 **이미 있는 4개 계절 색버퍼의 값만 바꾸는 일**이므로
드로우콜·프로그램·메모리 델타가 0이다.

### 3.5 결손 3 — 볼록·매끄러운 실루엣에 군집 리듬이 없다

수묵 모드의 실루엣 먹선은 깊이 불연속을 따라간다. 등축구/원뿔은 실루엣이 매끄러운 볼록 곡선이라
**선 굵기 변주가 생길 여지 자체가 없다.** 원리 ①(약 일곱 개씩 모여 반원형)·②(포갠 점의 요철)를
지오메트리 실루엣으로 옮겨야 필선이 스스로 흔들린다. 기본 모드에서도 같은 문제가
"저폴리 디오라마"(감사 U7)로 나타난다.

### 3.6 불변 계약과 예산 (구현 라운드가 반드시 지킬 것)

| 항목 | 수치·규약 | 출처 |
| --- | --- | --- |
| 한양 부감 드로우콜 | ≤ 540 (focus 1000 / mid 900 / focusOut 540) | `tools/lib/render-budget-contract.mjs` |
| 한양 부감 삼각형 | ≤ 2,000,000 | 같음 |
| 한양 부감 프로그램 | ≤ 144 (그 외 상태 192) | 같음 |
| 현 나무 삼각형 회계 | `PINE_TRIS 24`, `BROAD_TRIS 20`, `FAR_TRIS 40` | `forest-crunch.js` |
| 숲 밀도 | 유지 — 민둥산 금지(확정 사용자 결정) | `docs/look-restoration-plan.md` |

**삼각형 여유가 사실상 없다.** 한양 40k 그루 × 24 tri ≈ 960k tri로, 부감 예산 2M의 절반을 나무가 이미 쓴다.
→ **캐노피 삼각형 증가는 원칙적으로 불가.** 같은 예산 안에서 형태를 바꾸는 것만 허용된다.

추가 함정:

1. **수묵 노멀 오버라이드 함정 (알파 카드를 쓸 때 치명적)** — `InkPass`는 `scene.overrideMaterial`로
   평범한 `MeshNormalMaterial`을 강제한다. `alphaTest`/`alphaMap`은 오버라이드 재질에 없으므로
   **알파 카드가 노멀·깊이 버퍼에서 솔리드 사각형이 된다** → 수묵 모드가 나무를 직사각형으로 트레이스하고
   DoF 깊이도 사각형을 읽는다. 탈출로는 이미 저장소에 있다: `allowOverride = false`인 전용 노멀 재질을
   객체별로 스왑하는 패턴(`ink.js`의 `instFadeNormalMaterial`·`lodScreenDoorNormalMaterial` 2건 선례,
   `allowOverride`는 three 0.185.1에 존재), 그리고 DoF는 `userData.dofDepthMaterial`
   (조건: `allowOverride === false`, `depthWrite !== false`).
   **비용: 수묵/DoF 경로에 프로그램 패밀리 2개 추가** — 감사 R8이 이미 "프로그램 +40~57" 회귀 상태이므로 값이 비싸다.
2. **그림자** — `alphaTest > 0`이면 three r185가 `map`/`alphaMap`을 공유 shadow depth 재질에 복사하므로
   알파 실루엣 그림자가 성립하고, `shadow-depth-texture-lifecycle.js`의 `needsTextureSilhouette`가
   그 경우를 이미 보존한다. **`alphaHash`는 그림자 실루엣이 안 된다.**
3. **`flatShading: true`는 커스텀 정점 노멀을 무효화한다** — 구형 노멀을 쓰려면 반드시 끈다.
   프로그램 개수는 불변이되 `FLAT_SHADED` 정의가 빠져 cacheKey 패밀리가 한 번 갈린다.
4. **`FOREST_VISUAL_RADIUS`(pine 1.55 / broad 1.97 / far 1.46 / rock 1.95)는 배치 수용 판정에 쓰인다**
   (`forest-crunch.js:291,339` — `mask()`·성벽 클리어런스에 그 반경을 넘긴 뒤 `continue`).
   프로토의 XZ 반경이 바뀌어 이 상수를 갱신하면 **수용되는 나무 집합이 달라져 골든 해시가 바뀐다.**
   worker==sync 동일성(결정론 *계약*)은 유지되지만 **골든 재기준이 필요하고, `check:worker`의
   `vegetationContract`가 같은 상수를 재검증한다.** → **프로토의 XZ 반경은 고정하고 형태만 바꾸는 것을 권장.**
5. **`instanceColor`는 이미 3채널을 계절 4버퍼로 다 쓴다** — per-instance 값을 추가하려면
   별도 `InstancedBufferAttribute`가 필요하고, 이는 셰이더 패치(→ 새 cacheKey 축)를 부른다.
6. **워커 계약** — 배치·계절색 크런치는 `populate.worker.js`가 소유하고 메인은 조립만 한다.
   **프로토 지오메트리는 메인 스레드 소유이므로 지오메트리 교체는 워커 버퍼·RNG 스트림을 건드리지 않는다.**
   반대로 계절색 팔레트 변경은 크런치 안에 있으므로 워커 코드 변경이며, `?worker=0` vs 워커 해시 게이트 대상이다.
   (관측된 함정: 워커 모듈은 vite HMR로 스테일해진다 — 코드 수정 후 sync만 PASS면 vite 클린 재기동.)

### 3.7 동시 진행 트랙과의 접점 (2026-07-25 작업 트리 실측)

이 리서치 시점에 `src/village/forest.js`와 `src/env/rim.js`가 **다른 트랙에 의해 미커밋 수정 상태**다.
나무 트랙이 충돌 없이 진행하려면 다음을 전제해야 한다.

- **대기 트랙**이 `buildForest`에 원경 소실 밴드를 추가했다(`farHazeBand(site)` → `createFarHazeUniforms` →
  `injectCloudShadow(mat, cloudU, farHaze)`, `setHaze`가 매 틱 최종 대기색을 주입). 나무·암괴 재질이
  방위별 최소 외곽 반경의 0.72~1.0 구간에서 대기색으로 소실된다.
  → **원리 ⑥(여백=대기 원근)의 상당 부분이 이 트랙에서 이미 처리된다.** 나무 트랙은 원경 소실을
  중복 구현하지 말고, 대신 그 밴드 *안쪽*의 값 층화(§3.4)에 집중한다.
  이 혼합은 조명 이후 색 경로에서 일어나므로 **수묵 모드의 raw beauty 휘도에도 그대로 반영된다**
  (원경 수관이 종이색으로 수렴 = 원리 ②·⑥에 유리). 노멀/깊이 버퍼는 건드리지 않으므로
  §3.3의 필선 문제와는 독립이다.
- **림 트랙**이 `src/env/rim.js`를 수정 중이다. §3.2의 `ORGANIC_NAMES` 누락 수정은 그 트랙 소관.
- 즉 나무 트랙이 실제로 소유해야 하는 파일은 **프로토 지오메트리(`forest.js`의 `make*Proto`,
  `generators/village/trees.js`, `gardens.js`, `bloom.js`, `env/trees.js`)와 계절 팔레트(`forest-crunch.js`)**다.
  재질 패치 체인은 다른 트랙이 쓰고 있으므로 새 패치 축을 추가하지 않는 후보(§4-B)가 통합 마찰도 가장 작다.

## 4. 기법 후보

### 후보 A — 브러시 실루엣 알파 카드 클러스터 (전 계층)

**조형 대응**: 원리 ①을 정면으로 구현. `송엽점`(7침 반원 로제트)·`협엽점`(5~6엽 부채꼴)을 절차 캔버스
알파 텍스처로 굽고, 캐노피를 그 카드 6~10장의 클러스터로 만든다. 구형 노멀 전사를 함께 적용.

- **기본 모드 발현**: 최상. 역광에서 카드 가장자리가 빛나 프레넬 림과 상성이 좋고, 실루엣이 톱니가 되어
  저폴리 인상이 사라진다.
- **수묵 모드 발현**: 원칙적으로 최상(붓점 실루엣이 곧 먹점 군집)이나, **§3.6-1 함정을 해결하지 않으면
  최악(직사각형 트레이스)**. 해결에 프로그램 패밀리 2개가 든다.
- **비용**: 삼각형은 오히려 감소 가능(카드 8장 = 16 tri < 현 24 tri). 그러나 **필레이트가 진짜 비용** —
  한양 40k 그루의 겹친 알파컷 프래그먼트는 부감에서 위험. 텍스처 +1~2(아틀라스), 재질 +0(공유 가능),
  프로그램 +2(수묵 노멀 / DoF 깊이 전용) + 그림자 depth 변형.
- **LOD 사슬**: 근경 카드 클러스터 → 중경 카드 수 축소(2~3장) → 원경 단일 빌보드 → 최원경 blob.
  전환마다 팝핑 위험, 스크린도어 페이드가 필요하고 그건 또 cacheKey 축이다.
- **결정론·계절·눈**: 배치 결정론 불변(지오메트리만 교체, 단 §3.6-4 반경 고정 필요). `instanceColor` 계절 4버퍼 생존.
  눈 profile `foliage` 패치는 알파컷 카드에서 재판정 필요(**미확인**).
- **리스크**: **높음.** 필레이트 미지수 + 프로그램 예산이 이미 회귀 중 + LOD 팝핑 + 알파 실루엣 그림자 검증.
  Phase 3.5 한 라운드에 전 계층 적용은 비현실적.

### 후보 B — 층운형 캐노피 패드 + 구형 노멀 (기하 어휘 교체, 알파 0)

**조형 대응**: 원리 ③을 기하로 번역. 소나무 = 살짝 굽은 줄기 + **옆으로 벌어진 납작한 잎덩이 층 2~3단**
(십장생도·조선 산수의 층운형). 활엽 = 단일 등축구 대신 **크기가 다른 덩이 3~4개의 비대칭 뭉치**(원리 ①의
군집 리듬을 저폴리로). 원경 blob = 표면에 요철을 넣어 "포갠 점"(원리 ②)을 암시.
모든 캐노피에 **`normal = normalize(position − canopyCenter)`를 구워 넣고 재질 `flatShading`을 끈다.**

- **기본 모드 발현**: 좋음. 구형 노멀이 캐노피를 하나의 둥근 덩이로 셰이딩해 패싯이 사라지고,
  프레넬 림이 덩이 가장자리를 따라 연속적으로 흐른다(현재는 면마다 끊긴다). 실루엣이 비대칭 뭉치가 되어
  다각형 인상이 크게 완화된다.
- **수묵 모드 발현**: **매우 좋음, 그리고 이 후보의 결정적 장점.** §3.3의 내부 폴리곤 필선이
  **셰이더 수정 없이 사라지고**, 남는 것은 깊이 실루엣 먹선뿐 — 원리 ④("먹은 실루엣에 몰린다")가
  자동으로 성립한다. 비대칭 뭉치 실루엣이 필선 굵기 변주를 만든다.
- **비용**: **드로우콜 +0, 프로그램 +0(패밀리 1회 갈림), 텍스처 +0, 메모리 ~0.**
  삼각형은 동일 예산 유지가 가능(패드 3단 저폴리 ≈ 현 24~36 tri 범위).
- **LOD 사슬**: 현행 사슬을 그대로 유지 — 근경/중경 개별 인스턴스(`nearR` 안) → 원경 클러스터 blob(`nearR` 밖).
  **런타임 전환이 없으므로 팝핑도 없다**(현행 구조의 자산).
- **결정론·계절·눈**: 배치 결정론 불변(§3.6-4 반경 고정 시 골든 해시까지 불변).
  `instanceColor` 계절 4버퍼·`patchSnow` foliage·`injectCloudShadow`·inst-fade 전부 그대로 생존.
- **리스크**: **낮음.** 주요 리스크는 (i) `flatShading` 해제가 지형·건물의 패싯 스케일 계약과 어긋나 보이는지
  (`look-grammar.md` §3 "패싯 스케일을 화면 안에서 균일하게" — 나무만 매끄러워지면 오히려 튈 수 있다.
  프로토 라운드가 A/B로 판정할 항목), (ii) 원경 blob 요철이 부감에서 노이즈로 보일 수 있음.

### 후보 C — 현 로우폴리 유지 + 셰이딩만 회화화

**조형 대응**: 원리 ④·⑤만 겨냥. 형태는 그대로 두고 램프 셰이딩·실루엣 프린지·계절색 값 층화로
회화적 인상을 만든다.

- **기본 모드 발현**: 보통. 색·톤은 나아지지만 **실루엣이 그대로라 "다각형 나무"라는 사용자 지적을 해소하지 못한다.**
- **수묵 모드 발현**: 계절색 값 층화(§3.4)만으로도 R7의 나무측이 상당히 개선된다. 그러나 §3.3의 내부
  폴리곤 필선은 **남는다**(램프는 노멀 버퍼를 바꾸지 않는다).
- **비용**: 거의 0. 팔레트 값 변경 + (램프를 쓸 경우) 셰이더 패치 1개 = cacheKey 축 +1.
- **LOD·결정론·계절·눈**: 전부 불변(팔레트는 크런치 소유 → 워커 변경 + 해시 재기준).
- **리스크**: 낮음. 단 **사용자 지시를 절반만 이행**한다.

## 5. 권고안

> **B를 축으로 하고, C의 값 층화를 동시에 넣고, A는 근경 소수 계층으로 한정한다.**
> 3.5-1 프로토 라운드는 **단계 0을 먼저 만들어 A/B 샷을 찍고**, 그 결과 위에서 단계 1·2를 판정한다.

**단계 0 — 비용 0의 선행 조치 (프로토 라운드 첫 커밋 후보)**
1. 모든 캐노피 프로토에 구형 노멀을 구워 넣고(`normalize(position − canopyCenter)`) 나무 재질의
   `flatShading`을 끈다 → §3.3의 수묵 내부 폴리곤 필선 소멸, 기본 모드 패싯 소멸, 림 연속화.
2. 계절색 팔레트의 휘도 폭을 거리·고도·수종에 따라 의도적으로 벌린다 → §3.4의 균질 회색 해소(R7 나무측).
3. `rim.js`의 `ORGANIC_NAMES`에 실제 마을 나무 그룹명(`village-trees`, `village-forest`/`forest-trees`,
   `village-bloom`)을 넣어 organic ×0.7이 실제로 걸리게 한다 → 숲이 건물급 림을 받는 §3.2 결함 해소.
   **단 `rim.js`는 림 트랙이 동시 편집 중이므로 이 항목은 그 트랙에 이관하고 나무 트랙은 손대지 않는다.**

이 세 가지는 **드로우콜·프로그램·삼각형 델타 0**이고, 2번만 워커 해시 재기준을 요구한다.
`look-grammar.md` §6의 투자 우선순위로 보면 **2급(채도·값 규율) 비용으로 4급(신규 에셋) 효과**를 낸다 —
이 라운드에서 가장 비용 대비 효과가 큰 지점이다.

**단계 1 — 실루엣 어휘 교체 (후보 B 본체)**
소나무 = 굽은 줄기 + 층운형 잎덩이 2~3단, 활엽 = 비대칭 덩이 뭉치, 원경 blob = 요철 표면.
**프로토의 XZ 반경(pine 1.55 / broad 1.97 / far 1.46)과 삼각형 예산은 고정**해 골든 해시와
예산 계약을 건드리지 않는다.

**단계 2 — 근경 한정 알파 카드 (후보 A의 안전한 부분집합)**
`focus` 링·마당 과실수·보호수·히어로 종가 주변처럼 **인스턴스가 수십~수백인 계층만** 브러시 실루엣
카드로 격상한다. 이 규모에서는 필레이트가 문제되지 않고, 수묵 노멀 재질 스왑 1개로 §3.6-1을 해결할 수 있다.
**한양 40k 산 숲에는 적용하지 않는다** — 예산과 프로그램 회귀(R8) 양쪽에서 감당이 안 된다.

**왜 A 전면 적용이 아닌가**: 사용자 지시는 "동양화적인 형태, 특히 수묵에서 잘 드러나게"다.
수묵에서 나무를 망치고 있는 것은 카드가 없다는 사실이 아니라 **면 노멀이 만든 내부 폴리곤선과
값의 뭉침**이며, 그 둘은 A 없이 0 비용으로 고쳐진다. 반대로 A를 40k에 전면 적용하면
`look-grammar.md` §5 금지 목록의 "성능을 이유로 통합자를 끄는" 상황(예산 초과 → 포스트 축소)을
자기 손으로 만들 위험이 있다.

**프로토 라운드 판정 조건 (3.5-1에 제안)**
- 조건: 석양 역광 + fog, 부감(한양·마을)과 근접(focus) 양쪽, 계절 4종, **수묵 모드 필수 포함**.
- 판정: (i) 수묵에서 캐노피 내부 폴리곤선이 사라졌는가, (ii) 수묵 수림에 농담 층위가 2단 이상 생겼는가,
  (iii) 기본 모드에서 나무가 건물·지형과 디테일 밀도 계약을 맞추는가, (iv) `calls`/`triangles`/`programs` 델타,
  (v) `?worker=0` vs 워커 해시.
- 게이트: `npm run check:pr`, `check:worker`(`vegetationContract`), `check:lod:app`(예산 계약),
  `check:winter:app`(눈 profile), `check:ink:app`, `check:rim`.
  직접 관찰: `tools/shoot-forest.mjs`, `shoot-trees.mjs`, `shoot-ecotone.mjs`, `shoot-ink.mjs`.
  (`tools/verify-forest.mjs`는 폐기 — 구 캐노피 쉘 전제.)

### 9.2 리서치안을 실측으로 수정한 네 가지

1. **링 1~2단 손수 덩이는 폐기했다.** §4-B가 상정한 "층운 패드"를 링 1단(위·아래 꼭지)으로 만들면
   측면 실루엣이 필연적으로 마름모가 되어 근경에서 결정 덩어리로 읽힌다(A/B 실측). 링 2단으로 바꿔도
   같은 삼각 예산에서 20면체보다 구 근사가 나쁘다. → **20면체(20 삼각 = 구 근사 최적해)를 위도별
   반경 프로파일로 조각하는 방식**으로 확정. 층운 2단은 프로파일의 허리로 만든다
   (pine 실효 반경 1.52 → 0.88 → 1.24 → 0.38).
2. **위도 knot은 ±0.618이다.** 20면체 정점 위도는 −1, −1/φ, 0, +1/φ, +1 다섯 밴드뿐이므로 프로파일을
   등간격(±0.5)으로 보간하면 authoring 값이 밴드에 실리지 않고 뭉개진다(허리가 사라져 통짜로 렌더됨).
3. **footprint가 배치 수용 판정에 쓰이는 계층은 "inward" 규칙이 필수다.** 최대 XZ 반경을 같게 맞춰도
   최대 반경 정점의 *방향*이 바뀌면 프로토 footprint가 커진다(마당 과실수 실측 +0.17m) → `check:yard`의
   PR #36 잔존율 계약 위반(village:7 3/5). 그 계층은 프로파일 ≤1·안쪽 지터·회전·lean·정규화 없음으로
   모든 정점이 구 `ico` 반경 이내에 머물게 한다(재실측 worst −0.024m, 잔존율 107.2%).
4. **삼각 예산은 §3.6의 추정보다 훨씬 여유가 있다.** §3.6은 "한양 40k 그루 × 24 tri ≈ 960k"로 계산했지만
   실측 인스턴스 수는 한양 부감에서 `forest-pine` 462 / `forest-broad` 319 / `forest-far` 118 /
   `scatter-pine` 1061 이다(40000은 목표식 캡이고 nearR 압축·마스크로 실제 채택수가 훨씬 적다).
   그래도 이 라운드는 예산을 늘리지 않았다 — 소나무는 24→20으로 오히려 줄었다.

### 9.3 판정 (§5 "프로토 라운드 판정 조건")

- **(i) 수묵 캐노피 내부 폴리곤 필선 소멸 — 충족.** 어휘 A/B(`ab-ink-near`·`ab-ink-far`)에서 구 어휘는
  원뿔 중앙선·등축구 면 경계·far 돔 facet이 모두 필선으로 드러나고, 신 어휘는 외곽 실루엣만 남는다
  (원리 ④가 자동 성립). 제품 `ink-focus`·`ink-aerial`에서도 캐노피 내부가 단일 워시다.
- **(ii) 수묵 농담 층위 2단 이상 — 충족.** 알베도 감마휘도 폭이 전 계절 +24% 확대되고 점유 밴드는
  여름 2 / 봄 3 / 가을 3 / 겨울 2→4다(`probe-palette.mjs`). 더 중요한 변화는 폭의 상당량이 **저주파
  고도축**으로 옮겨간 것 — 원경 클러스터 블롭은 멤버 평균이라 그루별 항이 상쇄되고 고도항만 살아남아,
  부감에서 능선·중사면·산자락이 서로 다른 밴드로 읽힌다(`village-aerial-sunset`·`season-autumn`).
- **(iii) 기본 모드 디테일 밀도 계약 — 충족.** `ab-pbr-*`에서 구 어휘의 면별 플랫 음영이 사라지고 덩이가
  하나의 둥근 볼륨으로 셰이딩된다. 제품 `focus-parcel`에서 8면체 마당 나무와 크리스마스트리 원뿔이
  모두 사라지고 프레넬 림이 덩이 가장자리를 연속으로 흐른다. 지형·건물의 패싯 스케일과 충돌하지 않았다
  (§4-B 리스크 (i) 해소 — 나무만 매끄러워도 튀지 않는다. 캐노피는 원래 유기물이므로 대비축이 맞다).
- **(iv) 드로우콜·삼각형·프로그램 — 계약 안.** 메시·재질 구성은 그대로여서 드로우콜 델타 0.
  `check:lod:app` 실측 한양 aerial `calls=508 / triangles=1,854,222 / programs=126`(예산 540 / 2M / 144),
  focus 1088 / 6.36M / 176, mid 571 / 2.37M / 176 — 전부 PASS.
- **(v) worker vs sync 해시 — 일치.** sync / 실제 module Worker / `?worker=0` 폴백 세 경로가 네 규모에서
  바이트 동일. **pick proxy 해시는 네 규모 모두 불변**(주거·필지·도로·논 소유권 불침해). 씬 해시는
  식생 지오메트리·instanceColor 변경분만큼 재기준했다(`tools/check-worker-contract.mjs` 주석에 근거 기록).

게이트: `npm run check` 58/58 · `check:worker` PASS(재기준 후) · `check:lod:app` PASS ·
`check:winter:app` PASS · `check:ink:app` PASS · `check:rim` PASS(마을 식생 organic ×0.7 확인).
