# 진경산수 수묵 렌더 계약

> - **상태**: 현재 계약 + 구현 근거 리서치
> - **기준일**: 2026-07-26
> - **범위**: 제품의 PBR↔수묵 표현 전환, 색공간·성능·접근성·검증

## 미학 원칙

cheoma의 수묵 모드는 3D 장면을 단순한 흑백 외곽선으로 바꾸는 필터가 아니다. 조선 진경산수의 관찰과 재구성 방식을 따라, 실제로 생성된 지형·건축의 특징은 보존하되 화면에서 읽혀야 할 산세와 여백을 선택적으로 강조한다.

1. **실경을 출발점으로 삼는다.** 중국 화보의 도식을 복제하기보다 현장에서 본 우리 산천의 지형적 특징을 바탕으로 한다.
2. **사실성과 표현성을 함께 둔다.** 정선은 실제 인왕산의 특징을 살리면서 치마바위를 높이고 보이지 않는 계류를 더해 화면을 더 힘있게 구성했다. 따라서 절차 지형의 계획이나 seed를 바꾸지 않으면서 명암 덩어리·능선·안개 여백을 렌더 단계에서 선별한다.
3. **모든 면을 같은 선으로 두르지 않는다.** 가까운 건물의 실루엣과 처마는 또렷하게, 먼 산의 내부 삼각면은 약하게 하여 저폴리 면분할이 펜선처럼 드러나지 않게 한다.
4. **여백은 대기 원근이다.** 인왕제색도의 산이 비와 안개로 비워진 공간 위에 떠오르듯, 밝은 종이색과 거리 감쇠를 정보의 부재가 아니라 깊이 표현으로 사용한다.
5. **붓질 어휘를 명암에 번역한다.** 수직 준법의 암벽, 짧은 횡선·점의 수목, 넓은 먹 번짐을 각각 실루엣, 숲의 중간톤, 종이 위 명암 덩어리로 번역한다.
6. **건축과 자연을 같은 붓으로 그리지 않는다(계화 界畵 / 남종화법).** 「동궐도」는 한 화면에서 건축·담장을 자로 그은 직선 선묘로, 배경 산수를 부드러운 필치로 그린다. 따라서 건축의 처마·공포·기와 골·담장 상단은 흔들림 없는 짙은 선묘를 받고, 수관·암괴·이엉은 내부 선을 오히려 거두어 톤 덩어리로 남긴다. 이것은 원칙 3의 강화판이며, 요소별 디테일 차등이 성능 타협이 아니라 정격 문법이라는 근거다.
7. **선 굵기는 조명에 종속된다.** 역광이 제품의 기본 프레이밍이므로 수묵도 그 역광을 선으로 번역한다. 해를 등진 면의 실루엣은 굵고 짙게, 해를 받는 면은 얇게 — 태양이 실제로 피사체 뒤에 있을 때만 나타나는 기하 게이트이며 Fresnel 림과 같은 광학 조건을 공유한다.
8. **최농과 최담은 한 화면에 동시에 있어야 한다.** 농담이 매체의 본체다. 균질한 중간 회색은 물에 푼 먹물이 아니라 회색 필터이며, 양자화 단계가 몇 개인지가 아니라 **씬 휘도가 그 단계를 실제로 점유하는지**가 판정 기준이다.

## 코드와 수명주기 경계

- `src/render/ink-state.js`와 가벼운 `src/api/render-style.js`는 Three·DOM 없는 `pbr | ink` 상태 어휘와 정규화만 소유한다.
- `src/render/ink.js`는 재사용 가능한 `InkPass`, 종이 texture, normal/depth 선별과 셰이더를 소유한다. 앱·Svelte·URL을 알지 않는다.
- `src/api/ink.js`가 외부 소비자에게 WebGL 수묵 pass를 공개한다. URL은 이 무거운 그래프가 아니라 `src/api/render-style.js`만 소비하며, shader warm 전용 `src/api/rendering.js`의 가벼운 import 계약도 유지한다.
- `app/src/engine/ink-mode-runtime.js`가 제품 전환, post pass 휴면, composer 삽입·제거, dispose를 소유한다.
- `app/src/components/RenderStyleToggle.svelte`는 키보드와 보조기기 상태를 표현하고 엔진 상태는 가지지 않는다.

`mode=ink`는 카메라의 `explore | focus`와 독립된 **표현 모드**다. 공유 URL은 수묵일 때만 `?mode=ink`를 기록하며 PBR은 파라미터를 제거해 기존 URL을 보존한다. 새로고침은 첫 준비 프레임 전에 URL 상태를 복원한다.

## 렌더·성능 불변식

- 기본 PBR 순서는 `Render → Grade/Rim → Bokeh → Bloom → Flare → Outline → Output`이다. 광학적 DoF가 먼저 조리개상을 만들고 그 뒤의 bloom이 센서·후처리 헤이즈를 더한다.
- 수묵 pass는 처음 요청할 때만 만든다. 축소 `InkBeautyCapturePass`가 `Render` 직후 선형 HDR 농담 원본을 한 번 복사하고, `Ink`는 `Outline`과 `Output` 사이에 삽입된다. `OutputPass`는 언제나 마지막 하나이며 ACES tone mapping과 sRGB 변환은 여기서 한 번만 한다.
- 수묵 셰이더의 종이색은 Output의 ACES 변환을 고려해 선형 HDR에서 역보정한다. 독립 `NoToneMapping` 소비자는 이 보정을 건너뛴다.
- 전환은 0.72초 동안 PBR 결과와 수묵 결과를 단조롭게 섞는다. 완전한 수묵 상태에서는 grade, Bokeh, bloom, flare fullscreen pass를 쉬게 하고 돌아올 때 불투명 수묵 화면 뒤에서 먼저 깨운다. Bokeh가 쉬면 내부의 반해상도 highlight prefilter와 source scatter도 함께 그리지 않는다. 농담은 post 전 raw beauty에서만 산출하므로 sleep 전후 출력이 픽셀 단위로 같다. 추가 scene render가 없는 Fresnel rim과 태양광은 raw beauty의 동적인 조명 일부로 유지한다.
- normal/depth pass는 Points, Line, Sprite, `depthWrite=false`, 명시적 제외 객체를 그리지 않는다. DoF가 `userData.dofDepthMaterial`로 원경 창불의 실제 광원 깊이를 받더라도 수묵 normal은 그 소스 전용 재질을 소비하지 않으므로 창불이 표면 윤곽이 되지 않는다. 넓은 태양 글로우는 명시적 DoF 깊이도 소유하지 않고 배경/원경 gather로 남아 투명한 꼬리가 깊이를 가리지 않는다. 중간 `alphaHash` 인스턴스는 본 렌더와 같은 screen-door fade를 사용해 완전 불투명 가림막이 되지 않는다.
- normal target과 raw-beauty copy를 desktop 0.75배, compact/coarse 0.5배로 줄인다. 종이·최종 색 합성은 화면 해상도를 유지한다. PBR 복귀 뒤 copy pass도 비활성화되어 최초 PBR과 같은 pass work로 돌아간다.
- 종이 무늬는 결정론적이며 plan, terrain, village RNG를 소비하지 않는다. 수묵 전환이 마을 scene hash를 바꿔서는 안 된다.

## 이중 필법과 조명 종속 (원칙 6·7 구현 계약)

수묵 pass는 스크린 스페이스라 `material.userData.role`을 읽지 못하고, role 채널을 노멀 pass로 실어보내면 프로그램 축이 하나 늘어난다. 그래서 건축과 자연의 구분은 **이미 있는 노멀·깊이 버퍼에서 근사한다.** 판별식은 "이 화소를 지나는 화면 방향 중 표면 노멀이 정지한 축이 하나라도 있는가"이며, 목조 건축의 벽·지붕면·담장·기둥·기단이 전부 평면 또는 선직면(ruled surface)이라는 성질에 기댄다 — 자재를 따라가는 축이 곧 화원이 자를 대는 방향이다. 세 게이트를 곱한다.

1. **평판(ruled)** — 반경 `gyehwaRadius`(화면 px)의 8축(22.5° 간격)에서 양쪽 노멀 일치도의 최댓값을 `gyehwaPlateLo`~`gyehwaPlateHi`로 문턱 처리한다. 축을 45° 간격 4개로 줄이면 비스듬히 흐르는 기와 골이 축과 최대 22.5° 어긋나 판정이 끊기고 먹선이 점선이 된다.
2. **각진 모서리(hard)** — 1px 이면각이 충분히 큰 곳만 대상이다. 노멀 pass는 `overrideMaterial`이라 재질의 `flatShading`이 아니라 **지오메트리 정점 노멀**을 읽고, 지형·수관·화강암은 모두 매끄러운 정점 노멀이라 자연히 탈락한다. 이것이 원칙 3을 깨지 않는 이유다.
3. **가까운 쪽(nearSide)** — 깊이 불연속의 앞면만 자를 댄다. 이 게이트가 없으면 수관 실루엣 뒤의 **평탄한 지형 화소**가 1·2를 동시에 만족해 나무 테두리에 철사선이 돈다.

**반경이 화면 px 이라는 것이 이 계약의 핵심 조건이다.** 계화는 평면·선직면이 **화면에서 클 때만** 걸린다. 따라서 부감·원경에서는 건축이 작아져 판정 화소가 급감하고 기여가 미미해진다 — 이는 결함이 아니라 "근경 선묘 / 원경 붓질"이라는 §7.1 문법 그 자체이며 `detailFar` 억제와 같은 방향이다. 부감에서 계화가 약한 것을 회귀로 오진하지 말 것. 실측으로 이 비대칭은 크다: 판별식만 끈 격리 프레임과의 채널 평균차가 근경 2.52 / 부감 0.22다.

조명 종속은 **뷰공간 태양 방향 uniform 1개**로 한다. 이 pass가 노멀 pass의 기존 순회 안에서 씬의 태양(그림자 캐스터 `DirectionalLight` 우선, 없으면 최고 intensity)을 직접 찾으므로 **소비자 배선이 없고**, 태양이 없는 씬에서는 항등이다. 굵기와 농도 두 항이 `litWidth`/`unlitWidth` 한 쌍에서 파생되므로 둘을 1로 두면 기능 전체가 항등이 된다. 실측 기여는 **역광이 순광의 약 2배**다(근경 5.14 vs 2.40, 부감 1.61 vs 0.96 — 같은 카메라에서 uniform만 토글한 채널 평균차). 이 비율이 무너지면 태양 판독이나 뷰공간 변환이 깨진 것이다.

농담은 양자화 **직전 입력**을 `washLow`~`washHigh`로 정규화해 5단 전체를 주소지정한다. 이 정규화가 없으면 근경 프레임의 입력 휘도가 좁은 대역에 갇혀 5단 중 2~3단만 쓰이고 최담 밴드 점유가 1% 아래로 떨어진다(원칙 8 위반). `washLow=0, washHigh=1`은 정규화 이전과 수식적으로 동일한 항등이다.

지켜야 할 함정 둘:

- **평판 문턱은 8비트 노멀 버퍼의 양자화 한계 바로 위에 있다.** 동일 노멀 두 개의 최악 양자화 일치도와 2° 곡률 사이의 좁은 창을 쓴다. 노멀 타깃의 포맷·필터·정밀도를 바꾸는 변경은 **이 문턱을 함께 재측정해야 한다** — 그러지 않으면 판별이 조용히 무너져 전 씬이 한 필법으로 돌아간다.
- **먹선은 컴포저 컬러 체인이 아니라 `InkPass`의 별도 단일샘플 노멀/깊이 타깃에서 나온다.** 따라서 컴포저 렌더타깃에 MSAA를 켜도 먹선의 계단은 그대로다. 게다가 멀티샘플 깊이·노멀은 리졸브 없이 텍스처로 읽을 수 없고, 리졸브(평균)된 경계 노멀·깊이는 Sobel과 평판 판별식을 오히려 망친다. 수묵의 AA 레버는 **노멀/깊이 타깃 해상도(supersample)** 또는 합성된 먹선의 edge-space AA이며 MSAA가 아니다. 계화 선이 붓 흔들림을 걷어낸 만큼 1px 절벽이 그대로 드러나므로(실측: 근경 선 화소의 절벽 비율 7.8% → 18.6%, 같은 프레임의 PBR 경로는 33.4%), **선폭을 키워 계단을 가리는 것은 금지한다** — 그것은 필법을 되돌리는 것이다.

## 검증

```bash
npm run check:ink:app
npm run shoot:ink
```

실제 앱 게이트는 기본 PBR lazy 상태, 제품 Reference 모달의 기관별 근거·라이선스·안전한 외부 링크, 키보드 Enter/Space, `aria-pressed`, URL 동기화와 새로고침 복원, 단조로운 전환, 단일 Output-last 순서, 완전 수묵의 PBR pass 휴면, 부감·근경 sleep 전후 픽셀 동일성, PBR 복귀 뒤 beauty copy 휴면, shader/program 상한, 깊이 제외, 모바일 44px target, 화면 통계와 런타임 오류 0을 검사한다. PNG는 레포에 쌓지 않고 OS 임시 폴더에 남겨 직접 비교한다.

원칙 8은 **근접 프레임에서** 잠근다. 근접은 거리 감쇠로 여백을 벌 수 없어 균질한 중간 회색으로 가장 먼저 무너지는 지점이므로, 게이트가 망원 focus 캡처의 먹→종이 5등분 점유율과 톤 범위를 함께 검사해 최농과 최담이 동시에 존재하는지 확인한다. 부감 프레임의 통계만으로는 이 조건을 통과할 수 없다 — 하늘 여백이 최담 예산을 혼자 채워버리기 때문이다.

이중 필법과 조명 종속은 값·uniform 변경이므로 **프로그램·드로우콜 델타가 0이어야 한다**(실측 기준: 부감·근경 program count, 마을 draw call, ink 노멀 pass draw call 모두 불변). 비용은 ink 합성 프래그먼트의 텍스처 탭 증가로만 나타나고, 완전 수묵 상태에서 grade·bloom·Bokeh·flare가 자고 있는 예산 안에서 지불한다. 줄여야 할 때의 레버는 평판 판정 8축을 4축으로 낮추는 것이며, 그 대가는 위에 적은 점선화다. 헤드리스 절대 프레임 ms는 이 판정에 쓰지 않는다.
