## 배경 — 무엇이 잘못됐나 (사용자 진단, 2026-07-25)

Codex 구간에서 기능은 대량 추가됐지만(사찰 가람·시전·야드라이프·흙담·배수로·ㅁ자 반가·가옥 위계 등)
**시각 품질이 후퇴**했고 **성능이 불필요하게 과도**해졌다. 구체 증상:

1. **히어로 시네마틱 감흥 상실** — 첫 진입 연출이 밋밋해짐.
2. **DoF가 재현 안 됨** — 근접 보케가 의도대로 안 보임.
3. **림라이트 실종** — 메인 룩의 핵심(골든아워 역광 림)이 드러나지 않음.
4. **"숨쉬는 화면" 효과 소멸** — 모트·꽃잎·연기·흔들림 등 미세 생명감 사라짐.
5. **고증 미흡** — 리서치와 실제 구현 모두 부실 (신규 추가물 포함).
6. **성능 과다** — 물리 지오메트리 위주 재작성으로 예산 초과 의심.

원인 구조: Codex는 **비전 인식이 약하고 미감이 없다**. 스크린샷을 열어봐도 판정을 못 하므로
"수치 게이트 통과 = 완료"로 처리했고, 그 과정에서 룩을 정의하던 튜닝(수치로 표현 안 된 감성)이
"physical하게 정리"라는 명분으로 지워졌다.

### 운영 원칙 (이 계획 전체에 적용)

- **시각 판정은 반드시 비전 가능한 에이전트(Claude)나 사람이 한다.** Codex에게는 판정을 맡기지 않는다.
- **A/B 골든 비교가 기본 방법론**: `git worktree add /tmp/cheoma-golden 5ca668e` 로 구버전을 세워
  동일 seed·동일 카메라·동일 시간대 스크린샷 쌍을 뜨고, 나란히 놓고 판정한다.
- **골든은 바닥선이지 천장이 아니다 (2026-07-25 사용자 지시)**: "이전보다 안 좋아졌다"뿐 아니라
  **"절대적 기준으로 아직 미흡하다"**를 같은 무게로 판정한다. 판정표는 회귀 축(구:신 우열)과
  절대 축(레퍼런스·목표 무드 대비 완성도)을 분리해 기록하고, "구버전과 동등하지만 둘 다 미흡"인
  항목은 회귀가 아니라 **상향 과제**로 등재한다. 절대 축의 기준: 실제 골든아워 사진·수묵/영화적
  레퍼런스, 그리고 "three.js 공식 리트윗을 받을 한 컷"이라는 최종 목표.
- **장르는 `docs/look-grammar.md`가 확정한다 (2026-07-25)**: "빛과 대기로 통합된 회화적 스타일라이제이션".
  모든 Phase의 시각 판정에 그 문서의 3원칙(빛·대기 통합자 / 실루엣 우선 / 채도 규율)과
  리트머스("그림으로 읽히는가")를 적용한다. 장르 정합 위반은 골든과 같더라도 미달이다.
- **프로젝트 목표 4축에 정렬 (2026-07-25 사용자 재천명)**: ① 집의 디테일·**편집·재생성 경험**의 질
  ② three.js 커뮤니티 바이럴 클립 ③ 오리엔탈리즘(동양적 미감) 적극 활용 ④ 조선 고증 = 학습 자료 수준.
  → 판정·우선순위에 반영: focus-in 편집/리롤 웨이브의 체감 품질은 히어로와 동급 가중치로 다루고(Phase 2·3),
  고증(Phase 4)은 "장식"이 아니라 품질 기준으로 취급한다.
- **"물리적으로 올바름" ≠ "보기 좋음"**: physical 접근이 룩을 죽였으면 룩이 이긴다.
  단, 이번 구간에 들어간 구조 개선(소유권·수명주기·게이트)은 보존한다 — 되돌리기(revert)가 아니라 **재튜닝**이 기본.
- 각 Phase는 독립 PR 단위. 룩 변경과 구조 변경을 한 PR에 섞지 않는다.
- 성능 판정은 headless 절대 ms 금지 — draw call·program 수·결정론 해시(`tools/probe-drawcalls.mjs`,
  `tools/_probe-programs.mjs`, `tools/shoot-cityperf.mjs`)로 한다.
- 기존 체크 게이트(`npm run check:pr` → 머지 전 `check:full`)는 그대로 지킨다.

### 2-1 ~ 2-3 — 해소됨 (establishing 프레임이 자기 베일 뒤에 서 있었다, 2026-07-25)

**R6은 연출 비트가 지워진 문제가 아니었다.** 폴라 arc·조립 타이밍·DoF 추적·BGM 스웰은 모두 살아 있었고,

원인 귀속(매 rAF 실측, `seed=20260718&vseed=7`, siteR 128, 종가 maxDim ≈ 30.3):

| establishing 거리 / 카메라 y | 261.6m / 81.7m (고도 16.5°) | **111.2m / 31.1m (고도 12.2°)** |
| hold 중 fog near / far | 64 / 254 | 69 / 274 |
| **피사체 fog 계수 (t1)** | **1.00 = 완전 소거** | **0.21** |
| 착지 (불변) | 169.5m, 24°, fov 7 | 169.5m, 24°, fov 7 |

기제: `heroCameraFraming`이 7° 히어로 렌즈의 보정 dolly라 반경이 `1.85 → 5.60 × maxDim`(3.03배)로 늘었는데,

`startScale 1.62`가 곱해져 카메라가 262m — fog far 254m **밖** — 에 섰다. 즉 `startVillageReveal` 주석의

사실이 아니게 됐고, 두 값이 서로 다른 단위계에 묶여 있어 아무 게이트도 그것을 잡지 못했다.

1. **establishing을 화면 폭으로 authored**(`src/cinematic/architectural-reveal.js`). `startScale` 1.62 → **0.70**

   보니 씬은 읽히는데 프레임 전체에서 대기 원근이 사라져 어둡고 납작해졌다. 골든 t1의 아름다움은

## 진행 순서와 역할

```
Phase 0 (감사) → 사용자 우선순위 승인
  → Phase 1 (플래그십 룩)   ← 최우선, 단독 진행
  → Phase 2 (히어로)         ← Phase 1 뒤 (룩이 살아야 연출 판정 가능)
  → Phase 3 (생명감)         ← Phase 1과 부분 병행 가능 (파일 겹침 주의: post/rim vs motes/petals)
  → Phase 4 (고증)           ← 독립 병행 가능 (village/builder 도메인)
  → Phase 5 (성능)           ← 마지막 (룩 확정 후 다이어트해야 재작업 없음)
```

- **비전 판정·미감·연출 안무·고증 대조**: Claude(비전 가능) 또는 사람. Codex 금지.
