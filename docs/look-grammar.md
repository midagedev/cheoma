> - **상태**: 확정 방향 (2026-07-25 사용자 승인 라운드에서 명문화)
> - **적용 범위**: 모든 시각 작업의 판정 기준. 룩을 바꾸는 PR은 이 문서와의 정합을 리뷰 요건으로 한다.
> - **자매 문서**: `docs/look-restoration-plan.md`(현재 라운드), `docs/look-audit-2026-07.md`(증거)

## 1. 장르 선언

cheoma의 장르는 카툰도, 로우폴리 쇼케이스도, 리얼리스틱도 아니다.

> **"빛과 대기로 통합된 회화적(painterly) 스타일라이제이션"**
> — 형태는 절제하고, 시네마틱한 빛과 공기가 화면을 하나의 그림으로 묶는다.

같은 원리의 선례: 지브리 배경화(단순한 형태 + 정교한 빛), 겸재 진경산수(능선 겹침·운무 절단·여백).
제품 수묵(ink NPR) 모드가 이 스펙트럼의 명시적 "회화 끝단"을 맡았으나 2026-07-31 제거됐다 — 이제 그 끝단은 대기와 빛 자체가 담당한다(리서치 archive: [`ink-landscape.md`](ink-landscape.md)).

### 왜 이 장르인가 (비용 대비 효과)

| 선택지 | 판정 | 이유 |
| --- | --- | --- |
| 리얼리스틱 | ✗ | 절차 생성 에셋의 디테일 밀도로는 리얼 문턱을 못 넘고, 넘으려면 에셋 단위 비용이 폭발한다. |
| 풀 카툰(외곽선·플랫 컬러) | ✗ | "학습 자료 수준 고증"(목표 G4)의 재질·색 충실도와 충돌한다. |
| **회화적 스타일라이제이션** | ✓ | **빛·대기는 포스트 체인 + 셰이더 패치 몇 개로 전 씬에 적용되는 지렛대다.** 에셋을 하나하나 올리는 것보다 압도적으로 싸고, 이미 구현돼 있다(post.js·rim.js·fog·DoF). 로우폴리 기하는 빛이 살아 있으면 "의도된 절제"로 읽히고, 빛이 죽으면 "값싼 미완성"으로 전락한다 — 골든 A/B가 증거. |

## 2. 세 가지 통합 원칙

1. **빛과 대기가 통합자다.** 역광 림 + bloom 헤이즈 + DoF + fog가 화면 전체를 한 겹의 대기로 잇는다.
   어떤 오브젝트도 대기 밖에 있으면 안 된다(스카이돔 포함). 새 요소를 추가할 때의 첫 질문은
   "이것이 빛을 받는가"이지 "디테일이 충분한가"가 아니다.
2. **실루엣 우선 형태 언어.** 처마곡(앱 이름의 그것)이 프레임의 주선(主線)이다. 디테일 투자는
   실루엣과 큰 면(지붕선·용마루·담장 상단·능선)에 우선하고, 채움 디테일(마당 소품 등)은 절제한다.
   한 프레임 안에서 요소 간 디테일 밀도 계약을 일관되게 — 기와는 골까지 파면서 관목이 8면체면 장르가 깨진다.
3. **채도 규율.** 웜(주홍·금빛)은 하이라이트·림·발광에만. 그림자와 미드톤은 중성을 유지한다.
   높은 채도 포인트(등불·창불·단청)는 화면당 소수의 의도된 악센트다 — 대기와 무관하게 튀는 순간
   카툰 악센트가 되어 장르를 오염시킨다. 뇌록·주홍·수목 녹·하늘은 서로 구분되는 색상을 유지하되
   하나의 대기 안에서 만난다(단일 주황 워시 금지).

### 2.1 역광은 기하학적으로 성립해야 한다 (2026-08-07)

시그니처 역광은 "태양을 피사체 뒤에 둔다"로 끝나지 않는다. **그 뒤에 무엇이 서 있는지**까지
계산해야 성립한다.

히어로 랜딩은 종가 배면(`rotY + π + 55°`)에 태양을 고정해 왔는데, 배산임수 규약상 종가 배면은
곧 배산이다. 실측(vseed 20260716): 태양 고도 **9.51°**, 그 방위의 지형 수평선 **16.59°** —
태양이 능선 뒤 **7.08° 아래**에 묻혀 종가에 직사광이 한 줄기도 닿지 않았다. `rim.js` 의
`_directGate` 는 그림자 항이 0 이면 바닥값 0.45 로 눌리고, 무엇보다 씬 전체가 앰비언트만 받아
골든아워로 읽히지 않는다. 사용자 보고 "조립 후 림라이트가 거의 없다"의 원인이 이것이었다.

규율:

- **역광 방위를 상수로 두지 않는다.** 능선 윤곽은 시드마다 다르므로 어떤 상수를 골라도 다른
  부지에서 재발한다. 방위와 고도를 지형에서 함께 푼다(`src/env/hero-sun.js`). 목적함수는 실제로
  림을 만드는 두 게이트의 곱이다 — 고도 게이트(낮을수록 강함)와 역광 게이트(마주볼수록 강함).
  태양을 올리면 능선은 넘지만 골든아워를 잃고, 옆으로 돌리면 능선은 낮아지지만 역광을 잃는다.
- **넘길 능선이 없으면 아무것도 바꾸지 않는다.** 평지 부지는 프로필 고도 그대로 — 저고도
  골든아워를 불필요하게 소비하지 않는 항등 경로가 계약이다.
- **판정 축을 혼동하지 말 것.** 2026-07-31 라운드는 "정배면이 프레임을 실루엣으로 붕괴시킨다"를
  옳게 잡고 **방위**를 조정했지만, 프레임을 죽이던 축은 **고도**였다. 역광이 안 나올 때 물어야
  할 첫 질문은 "태양이 피사체 뒤인가"가 아니라 "태양이 지평선 위에 실제로 떠 있는가"다.

게이트: `npm run check:hero-sun`(순수, FAIL-first 픽스처 포함).

### 2.2 안티에일리어싱은 실루엣을 지우면 안 된다 (2026-08-07)

`rim.js` 의 프레넬 AA 는 화면 미분이 크면 림을 지웠다. 그런데 실루엣은 정의상 ndv 가 가장
급변하는 곳이라, 그 삭제는 림이 그려야 할 바로 그 선을 정조준한다. 히어로 정착(7° 렌즈·146 m)의
실측: `_aa` 평균 0.491, **실루엣 삼각형의 42.9% 가 완전 소멸**, 읽히는 비율 0.803 → 0.459.

규율: 고주파 실루엣은 **약하게** 만들되 지우지 않는다(`RIM_FRESNEL_AA.floor`). 진짜
안티에일리어싱은 에너지 보존형 Toksvig 항이 맡는다. 그리고 킥은 **선에만** 붙인다 — 낱개 장식
(막새·와구토·적새)에 같은 배수를 걸면 용마루가 금빛 점선이 되어, 그 AA 가 막으려던 스티플을
정확히 되살린다.

## 3. 요소별 규율

| 요소 | 규율 |
| --- | --- |
| 하늘 | 반드시 대기 원근에 참여한다. 지평 밴드는 fog색으로 수렴하고, 지형–하늘 경계에 하드컷이 보이면 실패. 하늘 채도가 지형을 누르면 안 된다. |
| 지형·숲 | 로우폴리 허용 — 단 패싯 스케일을 화면 안에서 균일하게. 원경은 대기(안개 층·능선 겹침)로 소실시킨다. 세계의 "끝"이 프레임에 보이면 실패(worldedge 연출로 마감, 지형 확장 금지). |
| 건물 | 실루엣(지붕곡·용마루)과 근접 부재(공포·창호·기단)가 디테일 투자처 — 이것이 G4(고증) 담당. 재질은 단순하되 빛 반응(림·스펙큘러)은 정확하게. |
| 입자·생명감 | 물리 크기 계약 유지 + 역광에서 발광(모트·연기·낙엽은 빛을 보여주는 장치다). 화면은 절대 완전 정지하지 않되 모든 모션은 미세 스케일. |
| 물·야간 발광 | 발광은 광원의 물리적 근거가 있어야 한다(달빛 스펙큘러·한지 투과). emissive 남용 금지. **야간 처마·기둥·담 깊이는 새 광원/재질군 없이 기존 달(직사)·반구 필·안개·grade/rim 균형만으로 읽힌다** — 호롱·한지 점광의 악센트 지위를 지키기 위한 제품 한계이며, 실측 야간 조도 복원이 아니다 (`atmosphere-profiles.js` night, village hemi/fill). |
| 농담·여백 | 안개 층과 역광이 만드는 명암 덩어리 위계와 여백이 생명 — 균질한 노출·균질한 회색은 실패. 이 축이 G3(동양적 미감)의 기준기다(수묵 모드가 맡던 자리를 2026-07-31 제거 이후 PBR 대기 경로가 이어받는다). |

## 4. 판정 리트머스 (모든 시각 게이트에 적용)

- **"이 프레임이 그림으로 읽히는가, 게임 스크린샷으로 읽히는가?"** — 그림이어야 한다.
- **리트윗 테스트**: 이 컷을 three.js 커뮤니티에 올렸을 때 "어떻게 만들었지?"가 나오는가.
- 회귀 테스트와 별개로, 장르 정합 위반(플랫 하늘, 언릿 덩어리, 대기 밖 채도 악센트, 디테일 계약 붕괴)은
  골든과 같더라도 미달이다.

## 5. 금지 목록

- 외곽선 토온 셰이딩의 전역 적용.
- 리얼 텍스처 추가로 장르 문제를 해결하려는 시도(비용 폭발 + 장르 혼선 가중).
- 빛 반응 없는 디테일 추가("어두운 데서 안 보이는 조각").
- 대기 규율 밖의 채도 악센트 남발.
- 성능을 이유로 통합자(림·헤이즈·fog·DoF)를 끄는 것 — 통합자는 이 앱의 본체다. 비용은 다른 곳에서 줄인다.

## 6. 투자 우선순위 (비용 대비 효과 내림차순)

1. **포스트·림·대기 튜닝** — 거의 0 비용으로 전 씬의 장르를 결정한다. (현재 Phase 1)
2. **채도 규율 정렬** — 팔레트·발광 강도 조정 수준. (창불·풀 틴트·단청 노출)
3. **디테일 계약 정렬** — 튀는 소수 요소만 선별 보정(예: 8면체 관목). 전면 리모델링 금지.
4. **에셋 신규 디테일** — 실루엣·근접 부재에 한해, 최후에.
